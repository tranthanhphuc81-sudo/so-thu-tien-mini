Lấy dữ liệu (Pull) — Trường hợp thành công

HTTP 200 · Dữ liệu đúng cấu trúc · Xử lý bình thường

✅ Trường hợp 1 — API trả về đúng, xử lý bình thường
Điều kiện: Server API hoạt động · Token hợp lệ · Dữ liệu đúng định dạng · Trong giờ bảo trì

Luồng xử lý:

// 1. Gọi backend của bạn
const res = await fetch('/api/debt?customerId=KH001', {
  headers: { 'Authorization': 'Bearer ' + userToken }
});

// 2. Kiểm tra HTTP status trước
if (!res.ok) throw new Error('HTTP ' + res.status);

// 3. Parse JSON
const data = await res.json();

// 4. Hiển thị
showResult(data.amount, data.dueDate);

Kết quả: Hiển thị số tiền tất toán / báo cáo công nợ cho người dùng.

❌

Lấy dữ liệu — Các lỗi thường gặp

Mỗi lỗi có nguyên nhân và cách xử lý khác nhau

🚧 Lỗi CORS (Cross-Origin Resource Sharing)

❌ Trình duyệt chặn request vì API không cho phép domain của bạn
Thông báo lỗi thường thấy:
Access to fetch at 'https://api.bank.vn' from origin 'https://yourapp.github.io' has been blocked by CORS policy

Nguyên nhân: API ngân hàng không khai báo header Access-Control-Allow-Origin cho domain của bạn.

Cách xử lý:

// ❌ KHÔNG làm thế này — bị CORS chặn
const res = await fetch('https://api.bank.vn/debt'); // BLOCKED

// ✅ Gọi qua backend server của bạn
const res = await fetch('https://your-worker.workers.dev/api/debt');
// Backend server gọi api.bank.vn — không bị CORS
Giải pháp nhanh: Cloudflare Worker — deploy trong 10 phút, miễn phí 100.000 request/ngày.

🔐 Lỗi xác thực (401 / 403)

❌ HTTP 401 Unauthorized — Token sai hoặc hết hạn

Nguyên nhân có thể:

  • Token JWT hết hạn (thường 1 giờ hoặc 24 giờ)
  • API key bị thu hồi
  • Sai format header (Bearer vs Basic)
// Xử lý: tự động refresh token khi hết hạn
async function callWithRetry(url) {
  let res = await fetch(url, { headers: getAuthHeader() });

  if (res.status === 401) {
    // Token hết hạn → refresh
    await refreshToken();
    res = await fetch(url, { headers: getAuthHeader() }); // thử lại 1 lần
  }

  if (!res.ok) throw new Error('HTTP ' + res.status);
  return res.json();
}
⚠️ HTTP 403 Forbidden — Không có quyền truy cập resource này

Nguyên nhân: Token hợp lệ nhưng role của user không được phép xem dữ liệu này (VD: CTV cố xem KH của CTV khác).

Xử lý: Hiển thị thông báo rõ ràng cho người dùng, không retry. Cần liên hệ NVTD để được cấp quyền.

⏱️ Timeout / API phản hồi chậm

⚠️ Request treo quá lâu, không có phản hồi

Nguyên nhân: Server API quá tải · Mạng chậm · API đang bảo trì không thông báo.

// Luôn đặt timeout khi gọi API bên ngoài
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 10000); // 10 giây

try {
  const res = await fetch(url, { signal: controller.signal });
  clearTimeout(timer);
  return await res.json();
} catch (e) {
  if (e.name === 'AbortError') {
    showToast('⏱️ API phản hồi quá chậm, thử lại sau');
  }
}
Khuyến nghị UX: Hiện spinner "Đang tải..." và cho phép người dùng hủy sau 10 giây.

📐 Dữ liệu trả về sai cấu trúc

⚠️ API trả về HTTP 200 nhưng dữ liệu không đúng như mong đợi

Nguyên nhân hay gặp nhất: Phía ngân hàng thay đổi tên field, thêm/xóa cột, đổi kiểu dữ liệu mà không báo trước.

// ❌ Không làm thế này — crash nếu field thiếu
const amount = data.earlyPayoffAmount; // undefined nếu đổi tên field

// ✅ Luôn có giá trị mặc định và kiểm tra kiểu
const amount = Number(data.earlyPayoffAmount ?? data.payoffAmount ?? 0);
if (!amount || isNaN(amount)) {
  showToast('⚠️ Không đọc được số tiền từ API');
  return;
}
Tốt nhất: Viết hàm parseApiResponse(raw) tập trung xử lý mapping, dễ sửa khi API thay đổi.

✅ Trường hợp 2 — Core banking gửi dữ liệu công nợ vào Firebase
Điều kiện: Firebase API key hợp lệ · Đúng đường dẫn · Rules cho phép

Phía ngân hàng gọi Firebase REST API:

# Curl từ phía ngân hàng / scheduled job

❌

Gửi dữ liệu — Các lỗi thường gặp

♻️ Dữ liệu bị ghi trùng

⚠️ Cùng một KH được push nhiều lần → tạo ra nhiều bản ghi

Nguyên nhân: Job bị chạy lại do lỗi mạng · Retry không có idempotency.

// ❌ Dùng push() — tạo key ngẫu nhiên → trùng
firebase.database().ref('/data/customers').push(customerData);

// ✅ Dùng set() với key cố định (mã KH từ ngân hàng)
// Nếu gọi lại với cùng key → ghi đè, không sinh bản mới
firebase.database().ref('/data/customers/' + customerId).set(customerData);
Nguyên tắc: Luôn dùng mã định danh từ hệ thống nguồn (mã KH ngân hàng) làm key Firebase — không tự sinh ID.

⚠️ Ghi dữ liệu một phần (Partial Write)

❌ Mạng đứt giữa chừng khi đang push 500 khách hàng → chỉ ghi được một phần

Hậu quả: App hiển thị danh sách không đầy đủ, NVTD không biết thiếu bao nhiêu.

// ✅ Dùng multi-path update — atomic: hoặc thành công toàn bộ, hoặc không ghi gì
const updates = {};
customers.forEach(c => {
  updates['/data/customers/' + c.id] = c;
});

// Ghi tất cả trong 1 request duy nhất
await firebase.database().ref().update(updates);

// Thêm checksum để verify sau khi push
updates['/data/meta/lastSync'] = { at: Date.now(), count: customers.length };
Kiểm tra: Sau khi push, đọc lại /data/meta/lastSync.count và so sánh với số dòng gốc để phát hiện mất dữ liệu.
⚠️ HTTP 429 Too Many Requests — Gọi API quá nhiều lần

Nguyên nhân: Ngân hàng giới hạn số lần gọi API trong 1 phút / 1 ngày. Nếu loop qua 1000 KH và gọi API từng người → bị block.

// ❌ Sai — gọi API riêng cho từng KH
for (const kh of customers) {
  await fetchDebt(kh.id); // 1000 request → bị block
}

// ✅ Đúng — gọi 1 request lấy toàn bộ, hoặc batch theo nhóm nhỏ
const allDebts = await fetchAllDebts({ date: today }); // 1 request
// Hoặc
const batches = chunk(customers, 50); // nhóm 50
for (const batch of batches) {
  await fetchBatch(batch);
  await sleep(1000); // nghỉ 1 giây giữa các batch
}

💉 Injection qua dữ liệu từ API

⚠️ Dữ liệu từ API chứa HTML/JS độc hại → XSS khi render ra giao diện
// Giả sử API trả về tên KH có chứa script
// name = '<script>document.cookie</script>'

// ❌ Render thẳng vào innerHTML — bị XSS
el.innerHTML = `<td>${data.name}</td>`;

// ✅ Luôn escape HTML trước khi render
function escHtml(str) {
  return String(str)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');
}
el.innerHTML = `<td>${escHtml(data.name)}</td>`; // ✅ an toàn
App này: Hàm escHtml() đã được dùng ở khắp nơi khi render dữ liệu KH — đã xử lý tốt.

🔥 Firebase Functions: Tất toán trước hạn có real-time không?

📌 Câu trả lời: Có — kiểu "on-demand real-time" (~200–400ms)

Firebase Functions không phải streaming real-time (như WebSocket hay Firebase Realtime DB listener), nhưng đủ nhanh cho hầu hết nghiệp vụ tài chính:

Loại real-timeCơ chếĐộ trễPhù hợp
On-demand (Firebase Functions) Người dùng bấm → gọi Function → nhận kết quả 200–400ms ✅ Tính tất toán khi cần
Streaming (WebSocket) Server chủ động đẩy liên tục ~10ms ❌ Quá phức tạp, cần infra riêng

Kết luận thực tế: Với nghiệp vụ "NVTD bấm tính tất toán → xem kết quả", độ trễ 200–400ms là hoàn toàn ổn. Không cần WebSocket.


Code mẫu Firebase Function — tính tất toán có cache 5 phút:

// functions/index.js
const functions = require('firebase-functions');
const admin = require('firebase-admin');
admin.initializeApp();

exports.calcEarlyPayoff = functions.https.onCall(async (data, context) => {
  // Xác thực Firebase Auth
  if (!context.auth)
    throw new functions.https.HttpsError('unauthenticated', 'Cần đăng nhập');

  const { customerId, payoffDate } = data;
  const cacheKey = `earlyPayoff_${customerId}_${payoffDate.replace(/-/g, '')}`;

  // Kiểm tra cache 5 phút trong Firebase
  const cacheSnap = await admin.database()
    .ref(`_cache/${cacheKey}`).once('value');

  if (cacheSnap.exists()) {
    const cached = cacheSnap.val();
    if (Date.now() - cached.ts < 5 * 60 * 1000) {
      return { ...cached.data, fromCache: true };
    }
  }

  // Gọi API ngân hàng (API key được giấu trong environment)
  const result = await callBankAPI('/early-payoff', { customerId, payoffDate });

  // Lưu cache
  await admin.database()
    .ref(`_cache/${cacheKey}`)
    .set({ data: result, ts: Date.now() });

  return { ...result, fromCache: false };
});

Gọi từ app (nvtd.html):

const calcEarlyPayoff = firebase.functions().httpsCallable('calcEarlyPayoff');

async function tinhTatToan(customerId, payoffDate) {
  try {
    const { data } = await calcEarlyPayoff({ customerId, payoffDate });
    showResult(data);  // fromCache: true/false
  } catch (err) {
    alert('Lỗi: ' + err.message);
  }
}

☁️ Firebase Storage cho file mẫu biểu

📌 Dùng Storage khi mẫu biểu là file .docx / .xlsx / .pdf / .html

Realtime Database chỉ nên dùng cho dữ liệu JSON/text. Nếu NVTD muốn upload file văn phòng thực sự, ta phải dùng Firebase Storage để lưu file và chỉ lưu metadata trong database.

1. Bật Storage

  1. Vào Firebase Console → Storage.
  2. Bật Storage và chọn region.

2. Thêm SDK Storage

Thêm vào head của cả nvtd.html và ctv.html:

<script src="https://www.gstatic.com/firebasejs/9.23.0/firebase-storage-compat.js"></script>

3. Cấu trúc lưu metadata

Trong Realtime Database, lưu metadata file để CTV có thể xem và download:

{
  "templateFiles": {
    "tpl1": {
      "name": "Phieu thu.docx",
      "url": "https://firebasestorage.googleapis.com/....",
      "type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "shared": true,
      "owner": "nvtd@sothu.app",
      "ts": 1710000000000
    }
  }
}

4. Upload file từ NVTD

Ví dụ load file và upload lên Storage:

function uploadTemplateFile(file) {
  const storageRef = firebase.storage().ref();
  const fileRef = storageRef.child('templateFiles/' + Date.now() + '_' + file.name);

  const uploadTask = fileRef.put(file);
  uploadTask.on('state_changed', snapshot => {
    const percent = Math.round(snapshot.bytesTransferred / snapshot.totalBytes * 100);
    // Hiển thị progress nếu cần
  }, err => {
    showToast('⚠️ Upload lỗi: ' + err.message);
  }, async () => {
    const url = await uploadTask.snapshot.ref.getDownloadURL();
    const metadata = {
      name: file.name,
      type: file.type || 'application/octet-stream',
      url,
      shared: true,
      owner: firebase.auth().currentUser.email,
      ts: Date.now()
    };
    await firebase.database().ref('/templateFiles').push(metadata);
    showToast('✅ Upload mẫu biểu thành công');
  });
}

5. Hiển thị cho CTV

CTV chỉ load các file có shared: true và dùng url để download:

firebase.database().ref('/templateFiles').on('value', snap => {
  const files = [];
  snap.forEach(child => {
    const v = child.val();
    if (v && v.shared) files.push({ id: child.key, ...v });
  });
  renderTemplateFiles(files);
});

// Khi render:
// <a href="${file.url}" target="_blank">${file.name}</a>

6. Rule Firebase Storage

Ở Firebase Console → Storage → Rules dán:

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /templateFiles/{fileId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null
                    && request.auth.token.email == 'nvtd@sothu.app';
    }
  }
}
Lưu ý: Storage dùng để lưu file thật, còn Realtime Database chỉ lưu link và metadata. CTV download file từ Storage, không lưu nội dung file trực tiếp trong database.

// functions/index.js
exports.getDebtReport = functions.https.onCall(async (data, context) => {
  if (!context.auth)
    throw new functions.https.HttpsError('unauthenticated', 'Cần đăng nhập');

  const { customerId } = data;
  const cacheRef = admin.database().ref(`_cache/debtReport/${customerId}`);
  const snap = await cacheRef.once('value');

  if (snap.exists()) {
    const { data: cached, ts } = snap.val();
    const ageMs = Date.now() - ts;
    if (ageMs < 30 * 60 * 1000) {
      // Trả cache + thông tin tuổi cache
      return {
        ...cached,
        fromCache: true,
        cacheAgeSeconds: Math.floor(ageMs / 1000)
      };
    }
  }

  // Cache cũ hoặc chưa có → gọi API ngân hàng
  const report = await callBankAPI('/debt-report', { customerId });
  await cacheRef.set({ data: report, ts: Date.now() });

  return { ...report, fromCache: false, cacheAgeSeconds: 0 };
});

Chiến lược 3 — Webhook endpoint (ngân hàng gọi vào):

// Ngân hàng gọi POST vào URL này khi KH thanh toán
exports.bankWebhook = functions.https.onRequest(async (req, res) => {
  // Xác thực chữ ký từ ngân hàng (HMAC-SHA256)
  const sig = req.headers['x-bank-signature'];
  if (!verifyBankSignature(req.rawBody, sig)) {
    return res.status(401).json({ error: 'Invalid signature' });
  }

  const { customerId, paidAmount, remainingDebt, paidAt } = req.body;

  // Cập nhật thẳng vào Firebase — app tự lắng nghe qua onValue()
  await admin.database().ref(`debtStatus/${customerId}`).update({
    remainingDebt,
    lastPaid: paidAmount,
    lastPaidAt: paidAt,
    updatedAt: Date.now()
  });

  // Xóa cache cũ để lần sau on-demand lấy số mới
  await admin.database().ref(`_cache/debtReport/${customerId}`).remove();

  res.json({ ok: true });
});

Code mẫu — Firebase Function (phía server)

// functions/index.js — chạy trên Firebase, API key không lộ ra ngoài
const functions = require('firebase-functions');
const fetch     = require('node-fetch');

exports.earlyPayoff = functions.https.onCall(async (data, context) => {
  // 1. Kiểm tra đã đăng nhập Firebase
  if (!context.auth)
    throw new functions.https.HttpsError('unauthenticated', 'Chưa đăng nhập');

  // 2. Lấy API key từ Firebase config — không hardcode, không lộ
  const apiKey = functions.config().bank.apikey;

  // 3. Gọi API ngân hàng
  const res = await fetch(
    `https://api.bank.vn/loans/${data.customerId}/payoff?date=${data.payoffDate}`,
    { headers: { 'X-API-Key': apiKey } }
  );

  if (!res.ok)
    throw new functions.https.HttpsError('unavailable', 'API ngân hàng lỗi: ' + res.status);

  return await res.json(); // trả thẳng về app
});

Code mẫu — Per-user rate limit trong Firebase Functions:

// Giới hạn mỗi nhân viên chỉ được gọi 10 lần/phút
exports.getCustomerDebt = functions.https.onCall(async (data, context) => {
  if (!context.auth)
    throw new functions.https.HttpsError('unauthenticated', 'Cần đăng nhập');

  const uid = context.auth.uid;
  const windowMs = 60 * 1000;
  const maxCalls = 10;

  const countRef = admin.database().ref(`_rateLimit/${uid}`);
  const snap = await countRef.once('value');
  const now = Date.now();

  if (snap.exists()) {
    const { count, windowStart } = snap.val();
    if (now - windowStart < windowMs) {
      if (count >= maxCalls) {
        const waitSec = Math.ceil((windowStart + windowMs - now) / 1000);
        throw new functions.https.HttpsError(
          'resource-exhausted', `Chờ ${waitSec}s rồi thử lại`
        );
      }
      await countRef.update({ count: count + 1 });
    } else {
      await countRef.set({ count: 1, windowStart: now });
    }
  } else {
    await countRef.set({ count: 1, windowStart: now });
  }

  return await callBankAPI('/debt', { customerId: data.customerId });
});

Firebase Transaction — ngăn ghi đè nhau:

async function recordPayment(customerId, amount, collectorUid) {
  // Transaction đọc-ghi nguyên tử, không thể bị ghi đè giữa chừng
  await admin.database().ref(`customers/${customerId}`)
    .transaction(current => {
      if (!current) return current; // abort nếu không có data
      current.totalPaid = (current.totalPaid || 0) + amount;
      current.lastPaymentBy = collectorUid;
      current.lastPaymentAt = Date.now();
      return current;
    });

  // Payment ghi riêng với idempotency key — không bao giờ xóa/sửa
  const idempKey = `${collectorUid}_${customerId}_${Date.now()}`;
  await admin.database()
    .ref(`customers/${customerId}/payments/${idempKey}`)
    .set({ amount, collectorUid, ts: Date.now() });
}
